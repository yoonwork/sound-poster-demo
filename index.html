      •

      •

    RF 프로토콜
    15바이트, 2~3번 보내고 받는 쪽에서 거르기
    Nordic ESB(2 Mbps, ACK·자동 재전송) 위에 우리 패킷을 실어요. ESB에도 CRC가 있지만 앱 CRC를 따로 둬서 나중에 BLE나 다른 칩으로 옮겨도 형식이 그대로 가요.
    
    
    
      
    
        
    
          
    바이트필드설명
    
          
            
    0version1
    
            
    1–2poster_id1~9999, 수신기가 Active Poster를 자동으로 바꾸는 기준
    
            
    3–6device_id칩 고유 번호(FICR) 아래 32비트
    
            
    7session켤 때마다 새 난수. 깨어나면 seq가 0부터 다시 시작해도 구분
    
            
    8–9seq이벤트마다 +1, 65535 다음 0
    
            
    10event1 START · 2 KEY_PRESS · 3 LONG_PRESS · 4 END
    
            
    11key_id1~112 (START·END는 0)
    
            
    12battery20 mV 단위 (150 = 3.00 V)
    
            
    13–14crc16CRC-16/CCITT-FALSE
    
              
        
    
      
    
      
    
        
    송신기 동작
    
        
      
          
    • 평소: 열은 LOW, 행은 풀업 + SENSE. 키가 눌리면 GPIO 이벤트로 깨어나 한 열씩 스캔해요.
      • 
          
    • KEY_PRESS는 눌리는 순간 바로 보내요(소리가 늦지 않게). 1초 넘게 누르고 있으면 LONG_PRESS를 한 번 더.
      • 
          
    • 한 번에 키 하나만 받아요. 손바닥으로 여러 키를 누를 때 생기는 유령 키를 막으려고요.
      • 
          
    • 10분 동안 안 누르면 END를 보내고 System OFF. 키가 끼여 눌린 채여도 30초가 지나면 활동으로 치지 않아서 꺼져요.
      • 
          
    • 수신기는 (device_id, session, seq)로 중복을 거르고, 32칸 창이라 순서가 조금 바뀌어 와도 받아요.
      • 
        
    
        
    CR2032 전류 계획
    
        
    
        
    
          
            
    꺼짐 (System OFF, GPIO로 깨움)0.3 µA
    
            
    켜짐 대기 (System ON, 이벤트 대기)1.2–1.5 µA
    
            
    송신 0 dBm / 수신(ACK)7.1 / 6.5 mA
    
            
    전지 용량 (Energizer CR2032)235 mAh
    
              
        
    
        
    칩 숫자는 nRF52832 데이터시트 값이에요. 계산으로는 누를 때 쓰는 전기는 아주 작고, 실제 수명은 대기 누설과 끼인 키(풀업으로 수백 µA)가 좌우해요. 그래서 3주차에 PPK2로 실측해서 숫자로 보고해요.
